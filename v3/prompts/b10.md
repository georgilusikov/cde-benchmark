VALUE NECESSITY CHECK:

Before decomposing the object, identify the smallest set of conditions that are necessary for the stated intended outcome to materially hold.

Use strict necessity logic:

"For each candidate condition: if this condition were false, could the stated outcome still materially be achieved?"

- If YES, remove it: it is desirable, helpful, or a best practice, not necessary.
- If NO, retain it as a necessary condition.

A necessary condition must be supported by:
1. an explicit requirement in the supplied context, OR
2. a direct logical implication of the stated outcome and supplied facts.

Do not invent:
- best practices,
- implementation choices,
- stakeholder preferences,
- future requirements,
- market expectations,
- quality targets,
- thresholds,
- verification gates.

Stop decomposing a value condition when it is specific enough to map to a concrete failure mode or falsifiable test.

Then map each retained necessary condition to the object's relevant components, stages, flows, or interfaces and continue with the normal B5 failure analysis.

If no useful value decomposition is needed, use the normal B5 analysis without forcing extra conditions.
